## 0. 왜 바꾸나: 세 사이트의 역할 분담

| 사이트 | 맡는 것 |
|---|---|

| 투자실무 (economics-practice) | 바뀌지 않는 구조와 계산법, 그리고 정책 다이얼의 **핵심 값**만 |

투자실무는 아래 정보를 본문에서 뺀다. 이 정보는 경제보고가 맡는다.
- 지역 목록, 한시 조치, 좁은 예외
- 진행 중인 사건(전쟁, 운송로 차단 등)
- 시장 수준(금리, 원자재 가격, 재고, 작황)

경제보고에는 이미 시계열 지표가 충분하다(미국 25, 주식 9, 금리 25, 원자재 44, 크립토 17, 한국·일본 13, 포지션 4). 따라서 이번 작업은 두 가지이다.
1. **제도 현황(policies)** 영역을 새로 만든다. API로 자동 수집되지 않고, 사람이 공식 자료로 확인해 적는 데이터이다.
2. 투자실무에서 넘어오는 **시계열 지표 몇 개**를 더한다(4절).

## 1. 새 데이터 파일: `registry/policies.yaml`

`indicators.yaml`과 같은 원칙을 따른다. **한 항목 = 한 다이얼**이고, 이 파일 한 곳만 고치면 화면이 따라간다. 파일 머리말에 필드 설명을 둔다.

### 1-1. 값 하나인 다이얼

```yaml
- id: kr-ltv-regulated
  area: re_loan                 # 화면 묶음 (아래 영역 목록)
  market: KR                    # KR / US / JP / GL(국제)
  label: "LTV · 규제지역 주택"
  value: "40%"
  detail: "생애최초는 70% (6개월 안 전입 조건)"   # 세부·예외는 여기에. 투자실무는 이걸 싣지 않는다
  effective: 2025-09-08         # 지금 값이 시행된 날
  expires: null                 # 한시 조치면 끝나는 날
  next_change: null             # 예고된 변경 {date, value, note}
  checked: 2026-10-18           # 마지막으로 원문과 대조한 날
  review_days: 90               # 다시 확인할 주기: 빠름 90 / 보통 180 / 느림 365
  grade: 공식                   # 공식 / 보도 / 미확인  (indicators 의 grade 와 같은 정신)
  sources:
    - {name: "금융위원회 보도자료 2025.9.7", url: "…"}
  history:                      # 바뀔 때마다 앞에 쌓는다
    - {until: 2025-09-07, value: "50%", source: "…"}
  practice: realestate-5        # 이 다이얼의 구조를 설명하는 투자실무 장 id
```

### 1-2. 목록형 다이얼

규제지역, 토지거래허가구역, 분양가상한제 지역 같은 것은 `value` 대신 `items`를 쓴다.

```yaml
- id: kr-regulated-areas
  area: re_zone
  market: KR
  label: "조정대상지역·투기과열지구"
  items: ["서울 25개 구", "경기 과천시", "…"]
  item_changes:
    - {date: 2026-07-01, add: ["경기 화성시 동탄구", "용인시 기흥구", "구리시"], source: "…"}
  checked: 2026-10-18
  review_days: 90
  grade: 보도
```

### 1-3. build가 하는 일
- `checked + review_days`가 오늘을 지나면 **확인 필요**로 표시한다. `#status`에도 올린다.
- `expires` 또는 `next_change.date`가 60일 안이면 **곧 바뀜**으로 표시한다.
- `history`의 맨 앞 `until`이 90일 안이면 **최근 바뀜**으로 표시한다.
- YAML 문장에 쉼표가 있으면 반드시 따옴표로 감싼다(기존 함정과 같다). build는 형식 오류를 만나면 멈추고 알린다.

### 1-4. 영역(area) 목록
- `re_loan` 부동산 대출
- `re_zone` 부동산 지역 지정
- `re_tax` 부동산 세금
- `re_lease` 임대차·보증
- `re_sub` 청약
- `kr_market` 한국 증권시장 제도 (거래 시간, 공매도, 시장경보, ETP 요건, 파생 진입 요건, 증거금률)
- `kr_tax` 한국 금융 세제
- `energy_policy` 에너지 정책 (OPEC+, 전략비축유, 유류세)
- `cb` 중앙은행 운영 (BOJ 국채 매입 등. 정책금리 자체는 이미 `cb_*` 지표가 있으니 중복하지 않는다)
- `us_market` 미국 시장 제도

## 2. 화면: "제도" 탭

기존 탭(us, stocks, rates, commod, crypto, world, position) 옆에 **제도** 탭을 더한다.

1. **맨 위 상자 "바뀌었거나 곧 바뀌는 것"**
   - 최근 90일 안에 바뀐 다이얼: `이전 값 → 현재 값 (날짜, 출처)`
   - 60일 안에 끝나거나 바뀌는 다이얼. 2026-10-18 기준 예:
     - 유류세 인하 종료 2026-11-30
     - 전세사기특별법 일부 시행 2026-11-12
     - 지방 스트레스 DSR 0.75%p 종료 2026-12-31
     - 서울 토지거래허가구역 2026-12-31까지
     - 1주택자 전세대출 보증비율 변경 2027-01-01
2. **영역별 표**: 현재 값, 세부, 시행일, 확인일, 등급, 출처, "구조 설명: 투자실무 ○장"
3. **확인 필요 목록**: 확인 기한이 지난 다이얼
4. **"오늘" 화면**: 최근 7일 안에 바뀐 제도가 있으면 한 줄로 알린다.

## 4. 더할 시계열 지표 (`indicators.yaml`)

이미 있는 것은 다시 만들지 않는다. 예: dgs10, jgb10, kr_10y, gold_fut, gold_silver, cushing, ng_storage, corn_cond, wb_*.

- 지표마다 기존 규칙대로 `grade`, `why`, `link`를 단다.
- 낡음 기준(월간 100일, 분기 220일)을 그대로 적용한다.
- LME 재고와 LME 공식 가격은 LME 사이트가 자동 접근을 막는다(Cloudflare). 보류하고 "알아 둘 것"에 적는다.

## 5. 업데이트 절차 (`update.sh`와 함께)

`update.sh`는 시계열 수집·계산·커밋을 한다. 제도 현황은 사람이 확인해야 하므로 **별도 점검 절차**를 둔다.

1. `python -m build.policies --due`(새로 만든다)가 확인 기한이 지났거나 30일 안에 닥칠 다이얼을 출력한다.
2. 그 목록만 원 기관에서 확인한다.
   - 부동산 대출: 금융위원회 보도자료
   - 지역·청약: 국토교통부, 청약홈
   - 세금: 재정경제부(구 기획재정부), 국세청, 국가법령정보센터
   - 증권시장: 한국거래소 공지, 금융위원회
   - 에너지: OPEC 보도자료, EIA, IEA
3. 값이 그대로면 `checked`만 오늘로 바꾼다. 바뀌었으면 옛 값을 `history` 앞에 넣고 `value`, `effective`, `sources`를 고친다.
4. 대책이 새로 나오면(예정에 없던 발표) 그날 바로 해당 영역 다이얼을 모두 점검한다.
5. `./update.sh`로 커밋·푸시한다. 커밋 메시지에 바뀐 다이얼 id를 적는다.

**투자실무에 알리는 규칙**: 투자실무 규칙(`economics-practice/js/rules.js`)에 같은 개념의 핵심 값이 있으면, 바뀐 id를 투자실무 쪽에도 알려야 한다. 핵심 값은 LTV, DSR, 스트레스 기본값, 한도 상한, 증권거래세 같은 것이다. 지시서 끝에 "투자실무 동기화 대상"으로 그 id 목록을 남겨 두고, 투자실무 세션이 그 목록으로 규칙과 예시 계산을 고친다.

## 6. 투자실무와의 연결 방식

- 경제보고의 다이얼마다 `practice: <장 id>`로 구조를 설명하는 투자실무 장을 가리킨다. 투자실무 주소는 https://jiseop-byeon.github.io/economics-practice/#/read/<장 id> 이다.
- 투자실무는 경제보고가 비공개이므로 본문에 링크를 걸지 않는다. 대신 "지금 설정은 원 기관에서 확인한다"로 남긴다.
- 이름은 두 쪽에서 같은 용어를 쓴다. 투자실무 용어 목록은 `economics-practice/js/glossary.js`에 있다.

## 7. 끝났는지 확인하는 기준

- `registry/policies.yaml`이 생기고, 3절 다이얼이 원문 대조 후 들어가 있다. 확인 못 한 것은 `grade: 미확인`으로 둔다.
- "제도" 탭에 영역별 표, "바뀌었거나 곧 바뀌는 것", "확인 필요"가 보인다.
- build가 확인 기한, 곧 바뀜, 최근 바뀜을 계산하고, YAML 형식 오류를 잡는다.
- 4절 지표 가운데 출처가 열리는 것은 추가했고, 막힌 것은 사유와 함께 "알아 둘 것"에 적었다.
- CLAUDE.md에 대상 확장, 제도 현황 구조, 점검 절차가 반영되었다.
